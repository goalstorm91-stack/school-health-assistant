# 운영 전 연결·검증 사항

## 시스템 경계

브라우저 → 학교용 인증 게이트웨이 → 업무 API → 학생정보 데이터베이스.
업무 API → 통계 집계/비식별 정책 → 별도 문서작성 서비스 → 외부 AI.

AI 서비스에 학생 데이터베이스 조회 자격증명을 부여하지 않습니다. 집계 함수와 개인정보 경계는 분리하며 외부 AI로 원본 방문, 이름, 식별자, 자유 메모를 전달하지 않습니다. 지금의 데모는 두 경로 모두 서버 연결이 없습니다.

## 인증·권한

학교 SSO와 MFA, 학교별 테넌트 격리를 구성합니다. 서버에서 매 요청의 사용자·학교·역할·리소스 권한을 검증합니다. 보건교사는 업무 기록을 관리하고, 보고서 열람자는 승인된 집계만 조회하도록 설계합니다. 브라우저 메뉴 숨김은 보안 경계가 아닙니다. 비활성 세션 만료, 계정 회수, 비상 접근 정책을 확정해야 합니다.

## 저장·거래

Student, Visit, VisitSymptom, VisitTreatment, InventoryItem, InventoryBatch, InventoryMovement, VisitAllocation, TaskSeries, TaskOccurrence, AuditEvent 엔터티를 분리합니다. 방문 저장에는 서버 발행 idempotency key 및 unique 제약을 사용하고, 기존 버전 확인으로 동시 수정 충돌을 검출합니다. 방문 수정과 재고 차감은 하나의 DB 트랜잭션으로 처리하며 수량 잠금 및 음수 금지 제약을 둡니다. 데모의 단일 탭 메모리 갱신은 다중 사용자 동시성을 보장하지 않습니다.

## 암호화·로그

HTTPS/TLS, 관리형 키 저장소를 이용한 저장 암호화 및 키 교체, 암호화된 백업과 복원 시험을 적용합니다. 실제 학생정보를 localStorage·URL·개발 로그·분석 도구에 기록하지 않습니다. 조회·수정·취소·내보내기는 서버 시간, 사용자, 목적, 대상 식별자, 작업 유형으로 감사 이벤트를 남기되 증상 메모 자체를 로그로 복제하지 않습니다. 감사 기록에는 별도 접근권한과 변조 방지 정책이 필요합니다.

## 보존·삭제

학교가 확정한 기록 종류별 보존기간, 삭제 승인, 법적 보존 예외, 백업 만료와 삭제 처리 증빙을 설정합니다. 구체적 기간은 임의로 정하지 않습니다. 학생 전출과 계정 회수, 첨부파일 등 확장 데이터의 삭제까지 함께 설계해야 합니다.

## AI 통계 정책

현재 허용 필드는 기간·대상·방문 건수·이용 학생 수·귀가 학생 수입니다. 최소 집단 기준은 3명 이상으로 조정하며, 기준 미만 집단과 작은 귀가 집계는 제외합니다. 이 단순 억제만으로 재식별 방지가 보장되지는 않습니다. 운영에서는 겹치는 질의의 차분 공격, 보완적 억제, 시간 구간 최소화, 질의 제한과 승인, 자유 입력 및 출력 검사를 추가 검토합니다. 원시 학생 명단 질의는 외부 AI가 아닌 권한 적용 내부 조회로 처리합니다.

## 외부 연동

Google Calendar는 교사 동의에 따른 OAuth, 최소 일정 권한, 서버 측 토큰 암호화, 동기화 충돌·삭제·재시도 정책이 필요합니다. 학생 식별 정보나 건강내용을 일정으로 보내지 않습니다. 현재 lib/health.ts의 CalendarConnector는 미연결 인터페이스이며 API 요청을 하지 않습니다.

## 출시 전 확인

학교 운영 담당자와 실제 업무 규칙, 보호자 인계 항목, 보존 정책을 확정하고 권한·보안 검토를 수행합니다. 동시 수정, 네트워크 실패, 백업 복구, 접근성, 실제 단말에서의 입력과 키보드 동작을 검증한 뒤 가상 데이터와 운영 데이터를 분리해 출시합니다.
